# Airlock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the starter shuttle's airlock a real, button-cycled room with steam, fog and
sound, and let the player cross its outer hatch into a suit-thruster spacewalk and come back.

**Architecture:**
- **The room** is an interior-space room: its own layout zone, a hatch at each end, three panels.
- **The cycle** is a pure `AirlockCycle` state machine owned by one `Airlock` node per airlock.
  That node drives everything that shows the cycle.
- **The outer hatch opening** is a portal. `ExteriorBuilder` builds a matching alcove on the hull.
- **The threshold:** crossing the outer hatch plane moves the avatar between interior space
  (`PLATING` mode) and the world (`SUIT` mode) with pure `Threshold` maths.

**Tech Stack:** Godot 4.5.1 (Forward+), GDScript, GUT 9.5.

**Spec:** `docs/superpowers/specs/2026-09-24-airlock-design.md`. Read it, and
`docs/design/visual-style.md`, first.

## Global Constraints

- Everything in `docs/design/visual-style.md` binds:
  - colours only from `InteriorPalette` (interior) or the new `HullPalette` (exterior);
  - props never reference `ShipGrid`, `InteriorLayout`, `InteriorBuilder` or `InteriorDressing`;
  - exactly three interior shaders;
  - interior render layer 2 with light cull mask 2;
  - no shadows.
- CLAUDE.md: no `#` comments in `.tscn`/`.tres`. Prove scene edits by runtime read-back.
- Branch `airlock`. Run the import pass after adding a `class_name`
  (`--headless --path who-knows --import`). Commit Godot's `.uid` files.
- Tests: `D:\git\whoknows\who-knows\run_tests.ps1 [-gselect=<file>]`. Baseline 425 passing.
- **Timings:** `SEALING` 0.7 s (leaves 0.5, bolts 0.2); `CYCLING` 2.8 s; `OPENING` 1.2 s
  (bolts 0.3, leaves 0.9).
- **Pressure:** 101 kPa. Going out `p = 101·(1 − u)²`; coming in `p = 101·(1 − (1 − u)²)`.
- **Room and hatch sizes:** clear height 1.9 m; hatch opening 1.0 × 1.85 m.
- **Closing and warnings:**
  - doorway zone 0.4 m either side of a hatch plane;
  - auto-close after 2 s empty;
  - motion warning amber above 0.5 m/s or 2°/s, coral above 3 m/s or 10°/s.
- **Suit:** 2.5 m/s²; assist cap 8 m/s; roll 90°/s. Entry speed cap 4 m/s; righting 0.4 s;
  threshold hysteresis 2 cm.
- **Layers:**
  - physics layer 5 (value 16) = `exterior_props`;
  - own-hull render layer value 4 (`ExteriorBuilder.OWN_HULL_LAYER`);
  - interior `InteriorKit.LAYER` = 2.

**Interfaces produced:**
- `AirlockSite.hatch_normal(grid: ShipGrid, coord: Vector3i) -> Vector3i`: the single horizontal
  face onto an empty cell, or `Vector3i.ZERO` if there are none or several.
- `InteriorLayout.AIRLOCK_ZONE := &"airlock"`, and `WallVariant.AIRLOCK`.
- Records carry `"hatch": bool`. It is true on both records of the airlock's doorway.
- `InteriorLayout.airlocks() -> Array[Dictionary]`: `{coord, hatch_normal, door_normal}`, where

- `InteriorProps.HATCH_HEIGHT := 1.85`, `InteriorProps.AIRLOCK_CLEAR := 1.9`.
- `InteriorBuilder.storey_offset(y: int) -> float` = `y × (STOREY_HEIGHT − CELL_SIZE)`.

  airlock zone it is `floor_y + AIRLOCK_CLEAR`.

**What to do:**
- **Layout:**
  - an airlock cell with a valid hatch gets the airlock zone;
  - `_room_of` treats the airlock zone as a room, so partitions and one doorway follow;
  - `_resolve_rooms` handles the airlock zone like a room but skips `_furnish_cell`, marks its
    doorway records `hatch`, and makes every other wall `AIRLOCK` except the hatch face (`HATCH`);
  - an inert airlock (no valid hatch) stays common space, as today.
- **Builder:** the airlock cell's ceiling slab sits so that its underside is at `ceiling_y`. The
  walls stay storey-high, since the space above the low ceiling is hidden. A doorway with `hatch`
  uses `HATCH_HEIGHT` for its opening and lintel.
- **Validator Rule 6** (warning): any `airlock` with `hatch_normal == ZERO`.

**Tests:**

- layout:
  - the starter's airlock zone, its hatch at +Z and its doorway at −Z with `hatch` on both
    records;
  - side walls `AIRLOCK`;
  - no `FEATURE`;
  - an inert airlock is common;
  - `airlocks()`;
- builder: the ceiling underside at `floor_y + 1.9` for the airlock only; the hatch opening's
  lintel bottom at `floor_y + 1.85`;

### Task 3: `AirlockCycle`, the pure state machine

**Files:**
- Create: `src/ship/airlock/airlock_cycle.gd`
- Test: `test/unit/test_airlock_cycle.gd`

**Interfaces produced:**
- `enum Stage { IDLE, SEALING, CYCLING, OPENING }`, `enum Side { NONE, INNER, OUTER }`.
- `const SEAL_TIME := 0.7`, `CYCLE_TIME := 2.8`, `OPEN_TIME := 1.2`, `LEAF_SHARE := 0.5 / 0.7`
  (sealing), `BOLT_SHARE_OPEN := 0.3 / 1.2`, `AUTO_CLOSE := 2.0`, `ATMOSPHERE := 101.0`.
- State:
  - `stage`, `time`;
  - `pressure` (kPa);
  - `open_side: Side`, the hatch open or opening;
  - `target_side: Side`, the hatch the current cycle ends at;
  - `sealing_side`;
  - `reversing: bool`;
  - `empty_time`;
  - the derived per-hatch amounts `inner_open` and `outer_open` (0..1) and `inner_bolts` and
    `outer_bolts` (0..1).
- `func press(panel: StringName) -> void`, where `panel` is `&"room"`, `&"inner"` (the corridor)
  or `&"outer"` (the hull). It queues intent.
- `func step(delta: float, doorway_clear_inner: bool, doorway_clear_outer: bool, room_empty: bool)
  -> Array[StringName]`. It advances and returns the cues fired this step, in order:
  - `&"leaves_closing"`, `&"leaves_shut"`, `&"bolts_home"`;
  - `&"cycle_start"`, `&"steam_jets"` (coming in only);
  - `&"bolts_out"`, `&"leaves_opening"`, `&"leaves_open"`;
  - `&"reversed"`, `&"blocked"`, `&"auto_close"`.
- `func prompt(panel: StringName) -> String`: *Depressurize*, *Pressurize*, *Reverse*,
  *Open hatch* or *Close hatch*, or empty when nothing applies.
- `func status() -> String`: *READY*, *CYCLING*, *CLEAR THE HATCH* or *VACUUM*.
- `func pressurized() -> bool`: pressure above 50.
- `static func motion_warning(speed: float, turn_rate_deg: float) -> Dictionary`:
  `{level: 0 | 1 | 2, text}`.

**Semantics:**
- `room` pressed while IDLE runs a cycle to the side opposite the current pressure (pressurized
  goes to OUTER, vacuum to INNER).
- An outside panel pressed:
  - if its side matches the pressure, it toggles that hatch (open with no cycle, or close);
  - otherwise it runs a cycle whose `target_side` is its side.
- A press mid-cycle reverses: the target swaps, pressure runs back at the same curve, and the
  cycle ends by opening the side that was open when it started (or none).
- `SEALING` does not start while the hatch being sealed has its doorway occupied (the `blocked`
  cue, once).
- Once IDLE with a hatch open, it closes after `room_empty` and both doorways have been clear for
  `AUTO_CLOSE`.
- Closing uses the same leaves-then-bolts timing as sealing.

**Tests:** every row above; the timings add up to 4.7 s; the curves at `u` = 0, 0.5 and 1; never
both open; cues in order.

**Commit:** `feat: the airlock cycle as a pure state machine`

   - 40% energy while the outer hatch is open;
   - the amber header lamps are visible only while cycling.
